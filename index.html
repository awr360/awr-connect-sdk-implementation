Overview

The AWR Connect Client JS SDK (adventist-inbox-sdk) lets you connect your own UI to the AWR Connect chat platform via a Custom Channel. You use the channelâ€™s connection key (channelId) and secret to send messages over REST and receive agent replies in real time over Socket.IO.

  • Real-time: Pass sessionId in config and call connect(); the SDK opens Socket.IO and joins a session room. Agent messages arrive via message; status via message_status; media finalize via message_media_ready.
  • REST: sendMessage(), sendMessageStatus(), and getConversation(sessionId, options); call connect() first.
  • Media: Use uploadMedia(file, { sessionId, mediaType }) (S3 upload-intents), then sendMessage(caption, { sessionId, messageType: 'media', mediaUrl, mediaType }). History/socket payloads may include time-limited mediaUrl / thumbnail.
  • Contact details: Pass contact: { country, language, attributes } in config (sent with every message) to fill the agent's contact card, and call updateContact({ sessionId, ... }) to change it without sending a message.
  • Use a stable sessionId per visitor. It must be a UUID (e.g. crypto.randomUUID()); guessable ids like user-123 are rejected. options.sessionId is required on every sendMessage(), uploadMedia(), and sendMessageStatus().
  • Requires adventist-inbox-sdk@0.6.0 or later. Obtain the connection key and secret when creating the Custom Channel in the webapp; the secret is shown only once.

Installation

From your project root:

pnpm add adventist-inbox-sdk

In the browser, load the UMD bundle from unpkg or a local build of awr-connect-custom-channel-js-sdk, then use AdventistInbox.AdventistInboxClient: 

<script src="https://unpkg.com/adventist-inbox-sdk@0.6.0/dist/index.umd.js"></script>

Quick start

Config uses baseUrl, channelId, and secret. For real-time receive, add sessionId (and optional visitorName). Register listeners before connect(). Send only after connection_ready fires (no payload). getConversation(sessionId, options) requires the client to be connected.

import { AdventistInboxClient } from "adventist-inbox-sdk";

const sessionId = crypto.randomUUID(); // must be a UUID; store it per visitor
const client = new AdventistInboxClient({
  baseUrl: "https://your-api.example.com",
  channelId: "your-connection-key",
  secret: "your-channel-secret",
  sessionId,
  visitorName: "Alice",
  contact: { country: "NG", language: "en", attributes: { platform: "web" } }, // optional
});

client.on("connection_ready", () => {
  // Only then send or load history
});
client.on("connection_error", (err) => console.error(err));
client.on("message", (msg) => console.log("Agent:", msg.textMessage, msg.mediaUrl));
client.on("message_status", (p) => console.log("Status:", p.socialMessageId, p.status));
client.on("message_media_ready", (msg) => console.log("Media ready:", msg._id));
client.on("error", (err) => console.error(err));

client.connect();

// After connection_ready:
const sent = await client.sendMessage("Hello!", { sessionId, visitorName: "Alice" });
console.log(sent.socialMessageId);
const { messages, pagination } = await client.getConversation(sessionId, { page: 1, limit: 20 });
client.disconnect();

Media upload & display

Upload flow: Call uploadMedia(file, { sessionId, mediaType, onProgress? }) after connect() / connection_ready. The SDK creates an upload intent, PUTs to S3 (single or multipart), then completes/polls until ready. Returns { mediaUrl, mediaType, thumbnail? }. Then send: sendMessage(caption, { sessionId, messageType: 'media', mediaUrl, mediaType }). Upload mediaType: 'image', 'audio', 'document'.

Size limits: Image 10 MB, audio 16 MB, document 25 MB. Allowed types: common image/audio MIME types and PDF, DOC/DOCX, PPT/PPTX, XLS/XLSX, TXT.

URLs: getConversation() and socket events may return time-limited (pre-signed) mediaUrl / thumbnail values usable in the browser. Prefer helpers getMessageDisplayUrl / getMessageFullUrl. Listen for message_media_ready when finalize is deferred.

Link lifetime: Treat media URLs as expiring (typically on the order of 1â€“2 hours depending on path). Refresh from history or wait for message_media_ready if a link stops working.

Display: This example renders images inline (<img>), audio with <audio controls>, and documents as download links. Use messageType and mediaType to choose the right UI.

Contact details

Agents see a contact card next to each conversation. The SDK can fill its Location and Language and add key-value attributes (such as app platform and version), shown read-only under Additional details.

// Defaults: sent with every message
const client = new AdventistInboxClient({
  baseUrl, channelId, secret, sessionId,
  visitorName: "Alex",
  contact: {
    country: "NG",        // ISO 3166-1 alpha-2 or alpha-3
    language: "en-US",    // ISO 639-1 or 639-3; region subtag is ignored
    attributes: { platform: "ios", appVersion: "3.2.1" },
  },
});

// One message only: merged over config.contact
await client.sendMessage("Hi", { sessionId, contact: { attributes: { screen: "checkout" } } });

// Without sending a message (e.g. after an app update)
const result = await client.updateContact({
  sessionId,
  attributes: { appVersion: "3.3.0", betaTester: null }, // null removes a key
});
if (!result.success) console.error(result.message);
  • Country and language fill empty values only. They are written when the contact has none, when the language is still the channel default, or when the value is one you sent earlier. A value an agent set in the inbox is kept.
  • Attributes merge per key; null removes a key. Up to 50 keys per contact. Keys start with a letter and use letters, digits, _, . or - (max 64 chars). Values are a string (max 500 chars), number or boolean.
  • The contact must exist. The visitor's first message creates it; before that updateContact returns { success: false } (HTTP 404). Put values in config.contact so they ride on that first message.
  • When sessionId is the client's own config.sessionId, updateContact also updates config.contact, so a later message does not revert the change.
  • On sendMessage, an invalid or unknown code is skipped and the message is still delivered. updateContact returns { success: false } with the reason instead.
  • Other metadata keys sent over the raw webhook are stored but not shown to agents. Use attributes for anything agents should see.

Raw REST: POST /webhook/custom/contact with body { sessionId, country?, language?, attributes? }. On POST /webhook/custom, put the same three keys in message.metadata.

API reference

constructor(config?: AwrConnectConfig)
Create a client. Pass baseUrl, channelId, secret; optionally sessionId, visitorName, requestId, contact.
setConfig(config: AwrConnectConfig): void
Set or update configuration.
connect(config?: AwrConnectConfig): void
Validate config and mark client connected. If sessionId is set, opens Socket.IO to /custom and joins the session room; connection_ready fires when the server acknowledges (no payload). 10s join timeout. Throws if baseUrl, channelId, or secret is missing.
disconnect(): void
Close Socket.IO (if open) and mark client disconnected.
isConnected(): boolean
Return whether the client is in a connected state.
isRealtimeReady(): boolean
When sessionId is set, true only after custom:join succeeds. sendMessage, uploadMedia, and sendMessageStatus wait for this automatically.
uploadMedia(file: File | Blob, options: UploadMediaOptions): Promise<UploadMediaResponse>
Upload via S3 upload-intents (create â†’ PUT â†’ complete/poll). Options: sessionId, mediaType ('image' | 'audio' | 'document'), visitorName?, requestId?, onProgress?(percent). Returns { mediaUrl, mediaType, thumbnail?, metadata? }. Then call sendMessage(caption, { sessionId, messageType: 'media', mediaUrl, mediaType }). Lower-level: createUploadIntent, uploadToS3, completeUploadIntent.
sendMessage(textOrContent: string, options: SendMessageOptions): Promise<{ success: boolean; message?: string; socialMessageId: string }>
Send a text or media message. options.sessionId is required (must not contain :). Options: visitorName?, messageType? ('TEXT' | 'media'), mediaUrl? (required when messageType is 'media'), mediaType? ('audio' | 'image' | 'video' | 'document'), socialMessageId? (auto-generated when omitted), contact? (merged over config.contact for this message). Always returns socialMessageId. Emits error on API failure.
updateContact(options: UpdateContactOptions): Promise<UpdateContactResult>
Set the contact's country, language and attributes without sending a message (POST /webhook/custom/contact). Options: sessionId plus at least one of country, language, attributes. Returns { success, message?, droppedAttributes? }; success: false when the contact does not exist yet or a field is invalid. Emits error on API failure. See Contact details.
sendMessageStatus(options: SendMessageStatusOptions): Promise<{ success: boolean; message?: string }>
Report delivery/read for an agent message. Options: sessionId, socialMessageId, messageType ('READ_UPDATE' | 'DELIVERY_UPDATE' | 'STATUS_UPDATE'), status ('READ' | 'DELIVERED' | 'SENT' | 'FAILED'), visitorName?.
markMessagesRead(sessionId: string, socialMessageIds: string[], visitorName?: string): Promise<{ success: boolean; failed: string[] }>
Sends READ_UPDATE for each id. Returns which ids failed.
getMessageStatus(sessionId: string, socialMessageId: string): MessageDeliveryStatus | undefined
Last cached status from local send, history, or message_status events.
getChannelInfo(): Promise<ChannelInfoResponse>
GET channel details (secret not included). Requires client connected.
getConversation(sessionId: string, options?: GetConversationOptions): Promise<GetConversationResponse>
GET paginated messages. Call connect() first. Options: page? (default 1), limit? (default 20, max 100). On 404 returns empty messages (no throw).
loadAllConversationMessages(sessionId: string, options?: { limit?: number; maxPages?: number }): Promise<SimplifiedMessage[]>
Fetches all pages (up to maxPages, default 100) and returns messages sorted oldest â†’ newest.

Types

interface AwrConnectConfig {
  baseUrl: string;
  channelId: string;
  secret: string;
  sessionId?: string;   // required for real-time receive; must be a UUID
  visitorName?: string;
  requestId?: string;   // sent as X-Request-Id
  contact?: ContactProfile; // sent with every message
}

type ContactAttributeValue = string | number | boolean;

interface ContactProfile {
  country?: string;     // ISO 3166-1 alpha-2/alpha-3, e.g. "NG"
  language?: string;    // ISO 639-1/639-3; "en-US" → "en"
  attributes?: Record<string, ContactAttributeValue | null>; // null removes a key
}

interface UpdateContactOptions extends ContactProfile {
  sessionId: string;    // the contact must exist (created by the first message)
}

interface UpdateContactResult {
  success: boolean;
  message?: string;
  droppedAttributes?: string[]; // not saved: contact already has 50 keys
}

type MessageDeliveryStatus = 'sent' | 'delivered' | 'read' | 'failed';

interface MessageButton {
  id: string;
  title: string;
  action?: string;
}

interface SendMessageOptions {
  sessionId: string;    // required; must be a UUID
  visitorName?: string;
  messageType?: 'TEXT' | 'media';
  mediaUrl?: string;    // required when messageType is 'media'
  mediaType?: 'audio' | 'image' | 'video' | 'document';
  socialMessageId?: string | null; // auto-generated when omitted
  contact?: ContactProfile; // merged over config.contact for this message
}

interface SendMessageStatusOptions {
  sessionId: string;
  socialMessageId: string;
  messageType: 'READ_UPDATE' | 'DELIVERY_UPDATE' | 'STATUS_UPDATE';
  status: 'READ' | 'DELIVERED' | 'SENT' | 'FAILED';
  visitorName?: string;
}

interface UploadMediaOptions {
  sessionId: string;
  mediaType: 'image' | 'audio' | 'document';
  visitorName?: string;
  requestId?: string;
  onProgress?: (percent: number) => void;
}

interface GetConversationOptions {
  page?: number;
  limit?: number;
}

interface SimplifiedMessage {
  _id: string;
  senderType: 'CONTACT' | 'AGENT';
  messageType: string;
  textMessage?: string;
  mediaType?: string;
  mediaUrl?: string;
  thumbnail?: string;
  status?: string;
  socialMessageId?: string | null;
  seq?: number;
  buttons?: MessageButton[];
  metadata?: Record<string, unknown>;
  createdAt?: string;
  updatedAt?: string;
}

interface MessageStatusPayload {
  socialMessageId: string;
  status: MessageDeliveryStatus;
  messageType?: 'READ_UPDATE' | 'DELIVERY_UPDATE' | 'STATUS_UPDATE';
  sessionId?: string;
  timestamp?: string;
}

interface Pagination {
  currentPage: number;
  limit: number;
  totalMessages: number;
  totalPages: number;
  hasNextPage: boolean;
  hasPrevPage: boolean;
  nextPage: number | null;
  prevPage: number | null;
}

interface GetConversationResponse {
  messages: SimplifiedMessage[];
  pagination: Pagination;
}

interface ChannelInfoResponse {
  id: number;
  name: string;
  channelUid: string;
  channelType: string;
  channelConfig: Record<string, unknown>;
}

Events

The client extends EventEmitter. Subscribe with client.on(eventName, handler). Attach listeners before calling connect().

  • connection_ready â€“ first successful Socket.IO join (or REST-only ready). No payload.
  • connection_error â€“ connect or join failed (Error).
  • reconnecting / reconnected â€“ transport reconnect and room re-join (no payload).
  • error â€“ connection or request failures (Error).
  • message â€“ SimplifiedMessage when an agent/content message arrives for this session.
  • message_media_ready â€“ SimplifiedMessage when background media finalize completes; patch the bubble.
  • message_status â€“ MessageStatusPayload for delivery/read ticks on messages you sent.

Authentication & security

All requests use the channel secret in the X-AWR-Channel-Secret header (or Authorization: Bearer <secret>). Get the connection key and secret when creating the Custom Channel in the AWR Connect webapp; the secret is shown only once and must be stored securely.

Server-side: the API compares the secret using a timing-safe comparison to avoid leaking information. Media upload is rate-limited (e.g. 30 requests per minute per IP). Uploaded document filenames use an allowlisted extension from the validated MIME type, not the client filename.

Live example

Use the form below to try the SDK (or the same REST calls if the SDK is not loaded). Fill in your API base URL, channel ID (id), secret, and optionally session ID and visitor name.
