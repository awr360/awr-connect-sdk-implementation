Adventist Inbox SDK

Custom Channel client – documentation and example implementation for adventist-inbox-sdk@0.6.0

Overview Security Installation Quick start History Media Delivery & read Contact details API reference Types Events Authentication Live example

Overview

adventist-inbox-sdk connects your own chat UI to Adventist Inbox through a Custom Channel. With the channel's connection key (channelId) and secret, you send messages over REST and receive agent replies in real time over Socket.IO.

  • Real-time: put sessionId in config and call connect(). The SDK joins the session room; agent messages arrive on message, delivery/read ticks on message_status, finished media on message_media_ready.
  • REST-only: leave sessionId out of config; send and poll getMessageWindow().
  • History: getMessageWindow(sessionId, { intent, limit, beforeSeq, afterSeq }), paged by seq. getConversation is deprecated.
  • Media: uploadMedia(file, { sessionId, mediaType }), then sendMessage(caption, { sessionId, messageType: 'media', mediaUrl, mediaType }). Render received media through getMessageDisplayUrl / getMessageFullUrl.
  • Contact details: contact: { country, language, attributes } in config (sent with every message) fills the agent's contact card; updateContact() changes it without a message.
  • sessionId must be a UUID (e.g. crypto.randomUUID()), stored per visitor and passed to every sendMessage(), uploadMedia() and sendMessageStatus().

Security

Do not put the channel secret in browser JavaScript. Anyone who has it can read and write any session on the channel. Keep it on your backend and call Adventist Inbox from there. This demo asks for the secret in the page only so you can test a channel locally.

  • sessionId must be a UUID; guessable ids like user-123 are rejected by connect() and the send helpers.
  • baseUrl must be https://, except http://localhost / 127.0.0.1 for local development.
  • Media URLs: the helpers only return https: (and blob: for local previews). Never put a raw URL from a message into src or href.

Installation

pnpm add adventist-inbox-sdk

In the browser, load the UMD bundle from unpkg (or a local build of awr-connect-custom-channel-js-sdk) and use the AdventistInbox global:

<script src="https://unpkg.com/adventist-inbox-sdk@0.6.0/dist/index.umd.js"></script>
<script>
  const { AdventistInboxClient, getMessageDisplayUrl, getMessageFullUrl } = AdventistInbox;
</script>

Quick start

Register listeners before connect(). In real-time mode, send only after connection_ready (no payload).

import { AdventistInboxClient } from "adventist-inbox-sdk";

const sessionId = crypto.randomUUID(); // store per visitor and reuse
const client = new AdventistInboxClient({
  baseUrl: "https://your-api.example.com",
  channelId: "your-connection-key",
  secret: process.env.AWR_SECRET, // server-side only
  sessionId,
  visitorName: "Alice",
  contact: { country: "NG", language: "en", attributes: { platform: "web" } }, // optional
});

client.on("connection_ready", async () => {
  const { messages, hasOlder, oldestSeq } = await client.getMessageWindow(sessionId, { intent: "present", limit: 50 });
  renderHistory(messages);
});
client.on("message", (msg) => addBubble(msg));
client.on("message_status", ({ socialMessageId, status }) => updateTicks(socialMessageId, status));
client.on("message_media_ready", (msg) => patchBubble(msg));
client.on("reconnecting", () => showBanner("Reconnecting…"));
client.on("reconnected", () => hideBanner()); // missed messages are replayed as `message`
client.on("connection_error", (err) => console.error(err));
client.on("error", (err) => console.error(err));

client.connect();

// After connection_ready:
const { success, socialMessageId } = await client.sendMessage("Hello!", { sessionId, visitorName: "Alice" });
client.disconnect();

History (message window)

getMessageWindow(sessionId, options) calls GET /webhook/custom/channels/:channelId/contact/:sessionId/messages/window. Options: intent ('present' | 'older' | 'newer' | 'message', default 'present'), limit, beforeSeq, afterSeq, aroundSeq, aroundMessageId. It returns { messages, oldestSeq, newestSeq, hasOlder, hasNewer, anchor }.

const present = await client.getMessageWindow(sessionId, { intent: "present", limit: 50 });
if (present.hasOlder && present.oldestSeq != null) {
  const older = await client.getMessageWindow(sessionId, { intent: "older", limit: 50, beforeSeq: present.oldestSeq });
}
  • Page by seq, not page numbers. Order bubbles by seq when present.
  • Agent-only rows (internal notes) are filtered out by the SDK.
  • Non-OK responses throw, including 404 for a session that has no conversation yet. Treat that as empty history.
  • Window rows are raw API documents: pass them through toSimplifiedMessage() to normalize them and scrub unsafe media URLs, like socket messages.
  • After a reconnect the SDK fetches messages newer than the last window and emits them as message.

Media upload & display

Upload: uploadMedia(file, { sessionId, mediaType, visitorName?, onProgress? }) after connection_ready. The SDK creates an upload intent, PUTs to S3 (single or multipart), then completes and polls until ready, returning { mediaUrl, mediaType, thumbnail? }. Upload mediaType: 'image', 'audio' or 'document'. Then send it: sendMessage(caption, { sessionId, messageType: 'media', mediaUrl, mediaType }).

Limits: image 10 MB, audio 16 MB, document 25 MB. Allowed: common image/audio types and PDF, DOC/DOCX, PPT/PPTX, XLS/XLSX, TXT.

Display: use getMessageDisplayUrl(msg) for previews (thumbnail first) and getMessageFullUrl(msg) for full media. Both return '' for unsafe schemes. Received mediaType can be image, audio, video or document.

Deferred media: a message can arrive before its media is finalized. Listen for message_media_ready and patch the bubble by _id / socialMessageId, keeping the best URL with resolveDurableMediaUrl(incoming, existing). Media URLs are pre-signed and expire (around 1–2 hours); reload history to refresh them.

Delivery & read status

  • Your messages: sendMessage returns a socialMessageId (generated when you don't pass one). Ticks for it arrive on message_status as 'sent' | 'delivered' | 'read' | 'failed'; getMessageStatus(sessionId, socialMessageId) returns the last known one.
  • Agent messages: report that the visitor saw them with markMessagesRead(sessionId, socialMessageIds, visitorName?) (or sendMessageStatus for one message), so the inbox shows read ticks.
  • Idempotency: reuse the same socialMessageId when retrying a send; the API deduplicates on it.

Contact details

Agents see a contact card next to each conversation. The SDK can fill its Location and Language and add key-value attributes (such as app platform and version), shown read-only under Additional details.

// Defaults: sent with every message
const client = new AdventistInboxClient({
  baseUrl, channelId, secret, sessionId,
  visitorName: "Alex",
  contact: {
    country: "NG",        // ISO 3166-1 alpha-2 or alpha-3
    language: "en-US",    // ISO 639-1 or 639-3; region subtag is ignored
    attributes: { platform: "ios", appVersion: "3.2.1" },
  },
});

// One message only: merged over config.contact
await client.sendMessage("Hi", { sessionId, contact: { attributes: { screen: "checkout" } } });

// Without sending a message (e.g. after an app update)
const result = await client.updateContact({
  sessionId,
  attributes: { appVersion: "3.3.0", betaTester: null }, // null removes a key
});
if (!result.success) console.error(result.message);
  • Country and language fill empty values only. They are written when the contact has none, when the language is still the channel default, or when the value is one you sent earlier. A value an agent set in the inbox is kept.
  • Attributes merge per key; null removes a key. Up to 50 keys per contact. Keys start with a letter and use letters, digits, _, . or - (max 64 chars). Values are a string (max 500 chars), number or boolean.
  • The contact must exist. The visitor's first message creates it; before that updateContact returns { success: false } (HTTP 404). Put values in config.contact so they ride on that first message.
  • When sessionId is the client's own config.sessionId, updateContact also updates config.contact, so a later message does not revert the change.
  • On sendMessage, an invalid or unknown code is skipped and the message is still delivered. updateContact returns { success: false } with the reason instead.
  • Other metadata keys sent over the raw webhook are stored but not shown to agents. Use attributes for anything agents should see.

Raw REST: POST /webhook/custom/contact with body { sessionId, country?, language?, attributes? }. On POST /webhook/custom, put the same three keys in message.metadata.

API reference

new AdventistInboxClient(config?: AdventistInboxConfig)
Create a client: baseUrl, channelId, secret; optionally sessionId, visitorName, requestId, contact.
setConfig(config: AdventistInboxConfig): void
Set or replace config before connect().
connect(config?: AdventistInboxConfig): void
Validates config (throws on a missing field, non-https baseUrl or non-UUID sessionId). With sessionId, opens Socket.IO to /custom and joins the session room; connection_ready fires on the server's acknowledgement (10 s timeout). Without it, connection_ready fires at once (REST-only).
disconnect(): void · isConnected(): boolean · isRealtimeReady(): boolean
Close the socket; whether connect() is active; whether the room join succeeded. sendMessage, uploadMedia, sendMessageStatus wait for the join automatically; getMessageWindow does not.
sendMessage(text: string, options: SendMessageOptions): Promise<{ success; message?; socialMessageId }>
Send text or media. options.sessionId is required. Options: visitorName?, messageType? ('TEXT' | 'media'), mediaUrl? (required for media), mediaType?, socialMessageId? (generated when omitted), contact? (merged over config.contact). Emits error on API failure.
uploadMedia(file: File | Blob, options: UploadMediaOptions): Promise<UploadMediaResponse>
S3 upload-intent flow (create → PUT → complete/poll). Options: sessionId, mediaType ('image' | 'audio' | 'document'), visitorName?, requestId?, onProgress?(percent). Lower-level: createUploadIntent, uploadToS3, completeUploadIntent.
updateContact(options: UpdateContactOptions): Promise<UpdateContactResult>
Set country, language and attributes without sending a message (POST /webhook/custom/contact). Options: sessionId plus at least one of country, language, attributes. Returns { success, message?, droppedAttributes? }. See Contact details.
getMessageWindow(sessionId: string, options?: GetMessageWindowOptions): Promise<CanonicalMessageWindowResponse>
Seq-based history. Call connect() first. Throws on non-OK responses (404 for a session with no conversation yet). See History.
sendMessageStatus(options: SendMessageStatusOptions): Promise<{ success; message? }>
Report delivery/read for an agent message: sessionId, socialMessageId, messageType ('READ_UPDATE' | 'DELIVERY_UPDATE' | 'STATUS_UPDATE'), status ('READ' | 'DELIVERED' | 'SENT' | 'FAILED'), visitorName?.
markMessagesRead(sessionId, socialMessageIds: string[], visitorName?): Promise<{ success; failed: string[] }>
Sends READ_UPDATE for each id and returns the ids that failed.
getMessageStatus(sessionId, socialMessageId): MessageDeliveryStatus | undefined
Last known status from local sends, history or message_status.
getChannelInfo(): Promise<ChannelInfoResponse>
Channel details (no secret). Requires connect().
getConversation(sessionId, { page?, limit? }) · loadAllConversationMessages(sessionId, { limit?, maxPages? }) (deprecated)
Page-number history, kept for older integrations. Use getMessageWindow instead.
Helpers: getMessageDisplayUrl(msg), getMessageFullUrl(msg), resolveDurableMediaUrl(incoming, existing), isSafeMediaUrl(url), toSimplifiedMessage(payload)
Safe media URLs (https: / blob: only) and message normalization. Exported from the package and on the AdventistInbox global.

Types

interface AdventistInboxConfig {
  baseUrl: string;          // https (http only for localhost)
  channelId: string;        // connection key, not a numeric id
  secret: string;           // server-side only
  sessionId?: string;       // UUID; required for real-time
  visitorName?: string;
  requestId?: string;       // sent as X-Request-Id
  contact?: ContactProfile; // sent with every message
}

type ContactAttributeValue = string | number | boolean;

interface ContactProfile {
  country?: string;   // ISO 3166-1 alpha-2/alpha-3, e.g. "NG"
  language?: string;  // ISO 639-1/639-3; "en-US" → "en"
  attributes?: Record<string, ContactAttributeValue | null>; // null removes a key
}

interface UpdateContactOptions extends ContactProfile {
  sessionId: string;  // the contact must exist (created by the first message)
}

interface UpdateContactResult {
  success: boolean;
  message?: string;
  droppedAttributes?: string[]; // not saved: contact already has 50 keys
}

interface SendMessageOptions {
  sessionId: string;  // required; UUID
  visitorName?: string;
  messageType?: 'TEXT' | 'media';
  mediaUrl?: string;  // required when messageType is 'media'
  mediaType?: 'audio' | 'image' | 'video' | 'document';
  socialMessageId?: string | null; // generated when omitted
  contact?: ContactProfile;        // merged over config.contact for this message
}

interface UploadMediaOptions {
  sessionId: string;
  mediaType: 'image' | 'audio' | 'document';
  visitorName?: string;
  requestId?: string;
  onProgress?: (percent: number) => void;
}

interface GetMessageWindowOptions {
  intent?: 'present' | 'older' | 'newer' | 'message';
  limit?: number;
  beforeSeq?: number;
  afterSeq?: number;
  aroundSeq?: number;
  aroundMessageId?: string;
}

interface CanonicalMessageWindowResponse {
  messages: CanonicalMessage[]; // raw rows; normalize with toSimplifiedMessage
  oldestSeq: number | null;
  newestSeq: number | null;
  hasOlder: boolean;
  hasNewer: boolean;
  anchor: { intent: string; seq: number | null; messageId: string | null };
}

interface SimplifiedMessage {
  _id: string;
  senderType: 'CONTACT' | 'AGENT';
  messageType: string;      // lower-case, e.g. "text" | "media"
  textMessage?: string;
  mediaType?: string;       // "image" | "audio" | "video" | "document"
  mediaUrl?: string;        // scrubbed: https/blob only
  thumbnail?: string;
  status?: string;
  socialMessageId?: string | null;
  seq?: number;             // conversation order
  buttons?: { id: string; title: string; action?: string }[];
  visibility?: 'customer' | 'agent';
  metadata?: Record<string, unknown>;
  createdAt?: string;
  updatedAt?: string;
}

type MessageDeliveryStatus = 'sent' | 'delivered' | 'read' | 'failed';

interface MessageStatusPayload {
  socialMessageId: string;
  status: MessageDeliveryStatus;
  messageType?: 'READ_UPDATE' | 'DELIVERY_UPDATE' | 'STATUS_UPDATE';
  sessionId?: string;
  timestamp?: string;
}

Events

Subscribe with client.on(name, handler) before connect(); remove with client.off(name, handler).

  • connection_ready – first successful room join (or REST-only ready). No payload.
  • connection_error – connect, auth or join failed (Error).
  • reconnecting / reconnected – transport reconnect and room re-join (no payload). After reconnected, missed messages are replayed as message.
  • message – SimplifiedMessage for this session (agent-only notes filtered out).
  • message_media_ready – SimplifiedMessage when background media finalize completes; patch the bubble.
  • message_status – MessageStatusPayload for ticks on messages you sent.
  • error – request or connection failure (Error).

Authentication & CORS

Every request sends the channel secret in X-AWR-Channel-Secret (optional X-Request-Id from requestId). You get the connection key and secret when you create the Custom Channel in the Adventist Inbox webapp; the secret is shown once.

Browsers: add your page origin (exact http(s)://host[:port], no path) to the Custom Channel's allowedOrigins. On multi-instance deploys it can take about a minute to apply. Native apps send no Origin and are unaffected.

Live example

Fill in your API base URL, Channel ID (connection key) and secret. Open chat starts a real-time chat: history loads through getMessageWindow, agent replies arrive live, your messages show sent/delivered/read ticks, and agent messages are marked read. Use Attach to upload an image, audio file or document. The buttons below the form call each API once and print the result in the log.

The SDK loads from unpkg; if that fails the page tries the sibling local build ../awr-connect-custom-channel-js-sdk/dist/index.umd.js. Without either, the API buttons fall back to fetch() and Open chat is unavailable.
